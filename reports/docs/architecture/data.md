# Session data on disk

What each folder of a session's data holds.

Moved verbatim from `reports/CLAUDE.md` on 2026-10-11, when CLAUDE.md became a map. A part named in bold elsewhere in this text, such as **The map**, may now sit in another file in `docs/architecture/`; CLAUDE.md lists which file holds which part.

## Session Data Directory Structure

| Directory | Purpose | Key Files |
|-----------|---------|-----------|
| `inputs/` | User-provided and AI-parsed inputs | The console: session-config.json (with the accusation word for word, `accusationRaw`, `exposures`, and since phase 3 the classified `adjustments`, the totals check `ledgerCheck` and the `sessionClock`; the roster is stamped from the roster stop), director-notes.json, orchestrator-parsed.json, photo-descriptions.json (the director's per-photo descriptions, brief 2.2). The standalone skill writes its own shapes of the first three, beside selected-paper-evidence.json and character-ids.json |
| `fetched/` | Raw data from external sources | tokens.json, paper-evidence.json |
| `photos/` | The session photos as the preprocessor resized them (`preprocessPhotos`), which publish reads | the photo files |
| `analysis/` | The approved versions, and the standalone skill's working files | The console: weave.approved.json (the weave as the director approved it at the story meeting, brief 4.5) and map.approved.json (the map as the director approved it, brief 4.6), written at each approve. The standalone skill: image-analyses-combined.json, evidence-bundle.json, weave.json, article-outline.json |
| `summaries/` | The standalone skill's record summary | evidence-summary.json |
| `output/` | Final deliverables | The console: content-bundle.approved.json (the bundle as the director approved it at the article stop; compare it with the last `reviseContent`/`generateContent` response in `llm-log/` to see every change the director made). The standalone skill: content-bundle.json, article-metadata.json, article.html. The console publishes the report to `outputs/report-<id>.html`, outside the session folder |
| `llm-log/` | Per-call prompt/response log (`lib/observability/llm-call-log.js`), written on `llm_start` and rewritten on completion; disabled under Jest unless a test opts in. An ERROR record carries `diagnostics` at the record's TOP level, as a completion does — not nested inside `error`, which holds `{message, errorName, schemaErrors}`. `diagnostics.servedModels` names the model(s) that answered (the record's `model` is the alias asked for); `diagnostics.refusal` marks a declined call; `diagnostics.refusalSignal` marks a completed call that a refusal signal preceded | `<yyyymmdd-HHMMSS>-<context>-<callId8>.json` per call, index.jsonl (with `servedModels`) |
| the session folder itself | The stops log (`lib/stops-log.js`; R8, tasks 4.12a and 4.12c), which spec section 13's readout reads beside the approved weave, map and article and the call log: a pause line, `{at, kind: 'pause', stop, round, words}`, each time a run pauses at a new stop or a new round of one (`words` counted over the stop's view models by `lib/stop-pages.js`: the input review, the meeting, the character-IDs stop, the map and the desk; null at every other stop; at the map, where `words` is the page as it opens, the line also carries `wordsOpen`, the page with every synopsis open, piece 4, R6), and an action line, `{at, kind: 'action', stop, round, action}`, for each approve, reweave or send-back. `round` is the stop's round, `stopRoundOf` (`lib/workflow/state.js`), the round each of the director's notes records as `stopRound`. A run that arrives where the log's last line already has the director (a /resume replay, a rollback that reopens the stop they are at, as a rollback to the meeting or the map does under R9) writes no line. A fresh start's first pause is always a line, and it carries `fresh: true`: a forced `/start` appends to the run it replaced, and the readout measures the run from its last `fresh` line. A pause after a rollback that wrote its stop's output again (`rewritesStop`: the rollback's seed clears the channel the stop shows, as a rollback to the article does, and as an old-shape thread's rollback to the meeting does to its weave; it reads what the seed cleared, `lib/api-helpers.js` `rollbackSeedClears`, which the server hands the runner; fix round 3) is always a line, though the stop is in round 1 again. `at` orders the lines and joins `llm-log/index.jsonl`, and is never a time at a stop. Disabled under Jest unless a test sets its root | stops.jsonl |

For complete directory structure and file descriptions, see `PIPELINE_DEEP_DIVE.md#data-directory-structure`.
