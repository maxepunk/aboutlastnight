# The judges

The two truth-only judges (the story meeting's fact check and the article judge): the rule set they read, their truth criteria, what each sees, and the notes at the stops.

Moved verbatim from `reports/CLAUDE.md` on 2026-10-11, when CLAUDE.md became a map. A part named in bold elsewhere in this text, such as **The map**, may now sit in another file in `docs/architecture/`; CLAUDE.md lists which file holds which part.

**The judges read the rule set** (phase 3, brief 3.4). Each judge's system prompt opens as a writer's does, through `systemPromptOpening(theme, call, sessionConfig)` (brief 4.13b): the theme's identity line for its call, the part about this session (`<this-session>`), the world and the limits (`loadRuleSet('judge-arc' | 'judge-article', {theme})`), then its instructions; neither judge reads the brief or a writer's own part (`RULE_SET_CALLS['judge-arc']` and `RULE_SET_CALLS['judge-article']` are core only, the phase 4 spec's section 11; the article judge since brief 4.7a). **The list of the limits** (phase 18, R8): the limits file carries no codes, but the judges keep the codes their findings open with, because `leadingRuleIds`, `criteriaRules`, the verdict guard and the console's `LEADING_RULE_IDS` read them and stored sessions hold findings in that form. So each judge's instructions list all fifteen limits, by code and name, once, as one line right under the heading THE LIMITS (`truthCriteriaSection`): `limitsLine` prints one exported constant, `LIMIT_CODES` in `evaluator-nodes.js` (`{code, name}` in the order of `limits.md`), whatever the judge's criteria score, since a judge is for catching every breach (run 2b listed each judge only the limits its criteria named; run 2c took that back, as the spec's section 7 has it). `lib/__tests__/judge-limits.test.js` holds the constant equal to the bold lead-ins of `limits.md` (the entry for Nova taking no side adds "with the part about this session", which holds the rest of that limit), and holds each judge's printed list to the fifteen codes in order. Each criterion's key is unchanged and each is must-pass; since run 2h a question's line names its codes alone, since the heading over the questions says the limits must pass.
